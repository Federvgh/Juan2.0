Crear un Design Brief para el portfolio basándome en el entendimiento compartido alcanzado con /grill-me.

Pasos:
1. Pedime una descripción de lo que quiero lograr (o tomala del contexto si ya corrimos /grill-me)
2. Explorá el repositorio actual para entender el contenido existente (proyectos, imágenes, textos)
3. Escribí el Design Brief en docs/DESIGN-BRIEF.md con estas secciones:

## Estructura del documento

### Objetivo
Qué problema resuelve este sitio y para quién.

### Páginas y secciones
Lista de cada página con sus secciones, contenido esperado y comportamiento.

### Inventario de contenido
Proyectos existentes, imágenes disponibles, textos que necesitan redacción.

### Directrices visuales
Referencia al skill /frontend-design. Notas específicas de este brief.

### Interacciones y animaciones
Qué páginas tienen scroll-animation, qué tiene fade-in simple, qué es estático.

### Requisitos técnicos
Stack, hosting, formulario, analytics, SEO, performance targets.

### User Stories
Historias de usuario en formato: "Como [audiencia], quiero [acción], para [beneficio]"
Mínimo: visitante casual, reclutador/estudio, el propio Juan Pablo actualizando.

### MVP vs Nice-to-have
Separar claramente qué entra en la primera versión y qué queda para después.

4. Pedí feedback sobre el brief antes de avanzar a implementación
5. Si el usuario lo autoriza, crear un Issue en GitHub con el brief completo
